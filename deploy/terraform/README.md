# Terraform GKE Deployment

Terraform owns cloud infrastructure and cluster-level deployment concerns:

- GKE cluster and autoscaled node pool.
- Artifact Registry Docker repository.
- Argus Kubernetes namespace.
- Optional KEDA installation for future queue/custom-metric workers.
- Optional application of Kubernetes YAML generated by Aspirate.
- HPAs for continuous background workers generated from the Aspire AppHost names.

## Bootstrap

```bash
terraform -chdir=deploy/terraform init
terraform -chdir=deploy/terraform apply \
  -var='project_id=project-30b3b95e-ed2b-4573-98a'
```

## Generate App Manifests

```bash
dotnet tool restore
cd src/Argus.AppHost
aspirate init
aspirate generate --non-interactive --disable-secrets
```

## Apply App Manifests And Worker Autoscaling

```bash
terraform -chdir=deploy/terraform apply \
  -var='project_id=project-30b3b95e-ed2b-4573-98a' \
  -var='apply_aspirate_manifests=true' \
  -var='aspirate_manifest_dir=../../src/Argus.AppHost/aspirate-output'
```

Continuous task-lease workers are scaled by Kubernetes HPAs:

- `amass-worker`
- `asset-scoring-worker`
- `dns-resolver-worker`
- `finding-deduper-worker`
- `fingerprint-worker`
- `headless-spider-worker`
- `html-dom-spider-worker`
- `http-probe-worker`
- `js-extractor-worker`
- `regex-scanner-worker`
- `subfinder-worker`
- `wordlist-discovery-worker`

`http-worker` and `asset-storage-worker` remain event-driven ephemeral worker hosts. `validation-worker` remains an HTTP worker-side service for manual validation endpoints.
