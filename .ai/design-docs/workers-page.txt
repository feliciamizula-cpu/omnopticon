# SPEC-2-Workers-Page

## Background

Argus has many long-running reconnaissance workers, including Amass, Subfinder, DNS Resolver, HTTP Probe, HTML DOM Spider, JS Extractor, Wordlist Discovery, Headless Spider, Fingerprint, Validation, Asset Scoring, Finding Deduper, Regex Scanner, HTTP Worker, and Asset Storage Worker.

Workers already register and heartbeat through `Argus.RealtimeService`. Existing worker status records include:

- `WorkerId`
- `WorkerType`
- `Version`
- `RunningTasks`
- `MaxConcurrency`
- `LastSeenAt`
- `IsOnline`

The new Workers page must give operators a production-ready operational dashboard for all worker types. It must show running worker counts, desired scale numbers, min/max limits, current task load, worker health, and manual scale controls.

Important implementation decision:

- `Argus.RealtimeService` remains the read model for worker runtime status.
- Scaling state and scaling commands are added to Realtime because `/workers` already routes there.
- Actual runtime scaling is performed through a pluggable scaler adapter:
  - `NoOpWorkerScaler` for local Aspire/dev.
  - `KubernetesWorkerScaler` for production Kubernetes.
  - Optional later `DockerComposeWorkerScaler` or external deployment integration.

This avoids pretending that Aspire can dynamically spawn new worker projects at runtime. In local development, the UI can update desired scale and record commands, but actual replica changes require the hosting environment to support scaling.

## Requirements

### Must Have

- Add a new `Argus.Web` page at `/workers`.
- The page must use `ArgusGrid`.
- Each main grid row represents one worker type.
- The page must show all known worker types, even if zero instances are currently running.
- For each worker type, show:
  - Worker type
  - Display name
  - Runtime mode
  - Online worker count
  - Offline/stale worker count
  - Desired replicas
  - Min replicas
  - Max replicas
  - Total running tasks
  - Total max concurrency
  - Utilization percentage
  - Last heartbeat
  - Scaling status
  - Last scale command
- Include buttons to:
  - Scale up by one
  - Scale down by one
  - Set exact desired replicas
  - Pause/resume worker type
  - Refresh
- Manual scale actions must persist desired replica settings.
- Manual scale actions must create an audit/command record.
- The UI must not allow scaling below `MinReplicas`.
- The UI must not allow scaling above `MaxReplicas`.
- The UI must show whether the scaler actually applied the command or only recorded it.
- The UI must show stale/offline workers based on heartbeat age.
- The page must support search/filter by worker type.
- The page must support auto-refresh.
- The page must allow expanding a worker type to show individual worker instances.
- The backend must expose a summary endpoint optimized for the page.
- The implementation must not break existing worker registration/heartbeat behavior.

### Should Have

- Show summary cards above the grid:
  - Total worker types
  - Online workers
  - Desired replicas
  - Running tasks
  - Saturated worker types
  - Stale workers
- Add row color/status:
  - Healthy
  - Under-scaled
  - Over-scaled
  - Saturated
  - Stale
  - Paused
  - Scaling pending
  - Scaling failed
- Add a row context menu:
  - Scale up
  - Scale down
  - Set desired replicas
  - Pause
  - Resume
  - View instances
  - View recent events
- Add confirmation dialog for scale-to-zero and pause.
- Add snackbar notifications for success/failure.
- Record actor/user where identity is available.
- Add event publication for scale changes.
- Add tests for aggregation and scale boundary behavior.

### Could Have

- Per-program worker scaling.
- Per-worker-type concurrency overrides.
- Autoscaling policy configuration.
- Queue depth integration from RabbitMQ/task service.
- CPU/memory integration from orchestrator metrics.
- Worker logs link-out.
- Rolling restart button.
- Drain worker button.
- Kill stale worker record button.
- Predictive scaling based on backlog.

### Won't Have in MVP

- Full autoscaling engine.
- Per-program worker pools.
- Direct Docker socket control from the web app.
- Direct process spawning from Aspire dev dashboard.
- Worker log streaming.
- Worker binary deployment management.

## Method

## Architecture

### Current State

Existing behavior:

- Workers call `/workers/register`.
- Workers call `/workers/heartbeat`.
- `RealtimeStore` keeps worker status in memory and persists to `RealtimeDbContext`.
- Gateway already forwards `/workers` and `/worker-types` to `Argus.RealtimeService`.
- `Argus.Web` already has a reusable `ArgusGrid<TItem>` component.

### Target State

Add a Workers page that calls new Realtime endpoints:

```http
GET    /worker-types/summary
GET    /worker-types/{workerType}
GET    /worker-types/{workerType}/instances
PUT    /worker-types/{workerType}/scale-settings
POST   /worker-types/{workerType}/scale
POST   /worker-types/{workerType}/scale-up
POST   /worker-types/{workerType}/scale-down
POST   /worker-types/{workerType}/pause
POST   /worker-types/{workerType}/resume
GET    /worker-scale-commands?take=100
```

The Workers page should never compute authoritative scaling status by itself. The backend must aggregate runtime worker records, worker type catalog data, and scale settings into one DTO.

## Worker Summary Aggregation

### Health Rules

For each worker type:

```text
online = workers where IsOnline == true and LastSeenAt within heartbeat timeout
offline = workers where LastSeenAt is older than timeout
desired = scale settings DesiredReplicas
runningTasks = sum RunningTasks
maxConcurrency = sum MaxConcurrency
utilization = runningTasks / maxConcurrency * 100
```

Default heartbeat timeout:

```json
{
  "Workers": {
    "HeartbeatTimeoutSeconds": 45,
    "SaturationThresholdPercent": 90
  }
}
```

Health status priority:

```csharp
if (settings.IsPaused)
    return WorkerTypeHealthStatus.Paused;

if (lastCommand?.Status == "Pending")
    return WorkerTypeHealthStatus.ScalingPending;

if (lastCommand?.Status == "Failed")
    return WorkerTypeHealthStatus.ScalingFailed;

if (online == 0 && desired > 0)
    return WorkerTypeHealthStatus.Stale;

if (online < desired)
    return WorkerTypeHealthStatus.UnderScaled;

if (online > desired)
    return WorkerTypeHealthStatus.OverScaled;

if (utilization >= saturationThresholdPercent)
    return WorkerTypeHealthStatus.Saturated;

return WorkerTypeHealthStatus.Healthy;
```

### Aggregation Pseudocode

```csharp
public async Task<WorkersPageSummaryDto> GetSummaryAsync(CancellationToken ct)
{
    var now = clock.UtcNow;
    var heartbeatTimeout = options.HeartbeatTimeout;
    var catalog = workerTypeCatalog.GetAll();

    await using var db = await dbFactory.CreateDbContextAsync(ct);

    var workerRecords = await db.Workers.ToListAsync(ct);
    var capabilityRecords = await db.WorkerCapabilities.ToListAsync(ct);
    var settings = await db.WorkerScaleSettings.ToListAsync(ct);
    var recentCommands = await db.WorkerScaleCommands
        .GroupBy(x => x.WorkerType)
        .Select(g => g.OrderByDescending(x => x.RequestedAt).First())
        .ToListAsync(ct);

    var allTypes = catalog.Select(x => x.WorkerType)
        .Concat(workerRecords.Select(x => x.WorkerType))
        .Distinct(StringComparer.OrdinalIgnoreCase)
        .OrderBy(x => x)
        .ToArray();

    var rows = new List<WorkerTypeSummaryDto>();

    foreach (var workerType in allTypes)
    {
        var definition = workerTypeCatalog.Find(workerType);
        var typeWorkers = workerRecords
            .Where(x => string.Equals(x.WorkerType, workerType, StringComparison.OrdinalIgnoreCase))
            .ToList();

        var scale = await GetOrCreateScaleSettingsAsync(workerType, definition, ct);

        var instances = typeWorkers.Select(w =>
        {
            var isOnline = now - w.LastSeenAt < heartbeatTimeout;
            return new { Record = w, IsOnline = isOnline };
        }).ToList();

        var online = instances.Count(x => x.IsOnline);
        var offline = instances.Count(x => !x.IsOnline);
        var runningTasks = instances.Where(x => x.IsOnline).Sum(x => x.Record.RunningTasks);
        var maxConcurrency = instances.Where(x => x.IsOnline).Sum(x => x.Record.MaxConcurrency);
        var utilization = maxConcurrency <= 0 ? 0 : (runningTasks / (double)maxConcurrency) * 100;

        var lastCommand = recentCommands.FirstOrDefault(x =>
            string.Equals(x.WorkerType, workerType, StringComparison.OrdinalIgnoreCase));

        rows.Add(new WorkerTypeSummaryDto(
            WorkerType: workerType,
            DisplayName: scale.DisplayName,
            RuntimeMode: scale.RuntimeMode,
            OnlineWorkers: online,
            OfflineWorkers: offline,
            DesiredReplicas: scale.DesiredReplicas,
            MinReplicas: scale.MinReplicas,
            MaxReplicas: scale.MaxReplicas,
            RunningTasks: runningTasks,
            MaxConcurrency: maxConcurrency,
            UtilizationPercent: Math.Round(utilization, 1),
            IsPaused: scale.IsPaused,
            HealthStatus: ComputeHealth(...),
            LastSeenAt: typeWorkers.Count == 0 ? null : typeWorkers.Max(x => x.LastSeenAt),
            LastScaleCommandId: lastCommand?.CommandId,
            LastScaleCommandStatus: lastCommand?.Status,
            LastScaleMessage: lastCommand?.Message,
            SubscribedAssetTypes: definition?.SubscribedAssetTypes ?? [],
            ProducedAssetTypes: definition?.ProducedAssetTypes ?? [],
            RequiresHttp: definition?.RequiresHttp ?? false,
            SupportsCheckpoint: definition?.SupportsCheckpoint ?? false));
    }

    return new WorkersPageSummaryDto(
        WorkerTypes: rows.Count,
        OnlineWorkers: rows.Sum(x => x.OnlineWorkers),
        OfflineWorkers: rows.Sum(x => x.OfflineWorkers),
        DesiredReplicas: rows.Sum(x => x.DesiredReplicas),
        RunningTasks: rows.Sum(x => x.RunningTasks),
        MaxConcurrency: rows.Sum(x => x.MaxConcurrency),
        SaturatedWorkerTypes: rows.Count(x => x.HealthStatus == WorkerTypeHealthStatus.Saturated),
        StaleWorkerTypes: rows.Count(x => x.HealthStatus == WorkerTypeHealthStatus.Stale),
        PausedWorkerTypes: rows.Count(x => x.HealthStatus == WorkerTypeHealthStatus.Paused),
        WorkerTypes: rows);
}
```

## Scaling Behavior

### Scale Up

Endpoint:

```http
POST /worker-types/{workerType}/scale-up
```

Behavior:

```text
target = min(currentDesired + 1, maxReplicas)
persist desired target
create command record
call scaler
update command status
return command dto
```

### Scale Down

Endpoint:

```http
POST /worker-types/{workerType}/scale-down
```

Behavior:

```text
target = max(currentDesired - 1, minReplicas)
persist desired target
create command record
call scaler
update command status
return command dto
```

### Set Exact Desired Replicas

Endpoint:

```http
POST /worker-types/{workerType}/scale
```

Request:

```json
{
  "desiredReplicas": 3,
  "reason": "manual operator scale"
}
```

Validation:

```text
desiredReplicas >= minReplicas
desiredReplicas <= maxReplicas
workerType exists or is currently registered
```

### Pause

Endpoint:

```http
POST /worker-types/{workerType}/pause
```

Behavior:

```text
set IsPaused = true
set DesiredReplicas = 0 if MinReplicas == 0
if MinReplicas > 0, reject pause unless force option is later added
create scale command
call scaler to 0 when allowed
```

### Resume

Endpoint:

```http
POST /worker-types/{workerType}/resume
```

Behavior:

```text
set IsPaused = false
if DesiredReplicas == 0, set DesiredReplicas to max(1, MinReplicas)
create scale command
call scaler
```

Pseudocode:

```csharp
public sealed class KubernetesWorkerScaler : IWorkerScaler
{
    public string Kind => "Kubernetes";

    public async Task<WorkerScalerResult> ScaleAsync(WorkerScaleTarget target, CancellationToken ct)
    {
        var ns = string.IsNullOrWhiteSpace(target.Namespace)
            ? options.KubernetesNamespace
            : target.Namespace;

        var deployment = target.DeploymentName;

        var scale = await client.ReadNamespacedDeploymentScaleAsync(
            name: deployment,
            namespaceParameter: ns,
            cancellationToken: ct);

        scale.Spec.Replicas = target.DesiredReplicas;

        var result = await client.ReplaceNamespacedDeploymentScaleAsync(
            body: scale,
            name: deployment,
            namespaceParameter: ns,
            cancellationToken: ct);

        return new WorkerScalerResult(
            WorkerScaleCommandStatus.Applied,
            AppliedReplicas: result.Spec.Replicas,
            Message: $"Scaled deployment {ns}/{deployment} to {result.Spec.Replicas} replica(s).");
    }
}
```

### ExternalCommandWorkerScaler

Use when an external deployment system must apply scaling.

Behavior:

- Persist command as `Pending`.
- Publish event `WorkerScaleCommandRequested`.
- External scaler consumes event and calls callback endpoint later.

This is useful for Docker Compose, CI/CD, or a custom orchestrator.

Future callback:

```http
POST /worker-scale-commands/{commandId}/complete
```

### Auto Refresh

```csharp
private WorkersPageSummaryDto? _summary;
private WorkerTypeSummaryDto? _selected;
private WorkerTypeSummaryDto? _scaleDialogWorker;
private bool _loading;
private bool _autoRefresh = true;
private string _filter = "";
private PeriodicTimer? _timer;
private CancellationTokenSource? _cts;

private IReadOnlyCollection<WorkerTypeSummaryDto> FilteredRows =>
    _summary?.WorkerTypes
        .Where(w =>
            string.IsNullOrWhiteSpace(_filter) ||
            w.WorkerType.Contains(_filter, StringComparison.OrdinalIgnoreCase) ||
            w.DisplayName.Contains(_filter, StringComparison.OrdinalIgnoreCase))
        .ToArray()
    ?? [];

private async Task RefreshAsync()
{
    _loading = true;
    try
    {
        _summary = await WorkersApi.GetSummaryAsync();
    }
    catch (Exception ex)
    {
        Logger.LogWarning(ex, "Failed to load workers summary");
    }
    finally
    {
        _loading = false;
    }
}

private void StartPolling()
{
    _cts = new CancellationTokenSource();
    _timer = new PeriodicTimer(TimeSpan.FromSeconds(5));

    _ = Task.Run(async () =>
    {
        while (!_cts.IsCancellationRequested && _timer is not null)
        {
            try
            {
                if (!await _timer.WaitForNextTickAsync(_cts.Token))
                    break;

                if (_autoRefresh)
                {
                    await InvokeAsync(RefreshAsync);
                    await InvokeAsync(StateHasChanged);
                }
            }
            catch (OperationCanceledException)
            {
                break;
            }
            catch (Exception ex)
            {
                Logger.LogDebug(ex, "Workers polling failed");
            }
        }
    });
}

public async ValueTask DisposeAsync()
{
    if (_cts is not null)
    {
        await _cts.CancelAsync();
        _cts.Dispose();
    }

    _timer?.Dispose();
}
```

## Security

### Authorization

For MVP, wire endpoint authorization to whatever auth exists in the app. If no auth exists, structure code so policies can be added later.

Recommended policies:

```text
Workers.Read
Workers.Scale
Workers.Admin
```

Endpoint access:

```text
GET /worker-types/summary -> Workers.Read
GET /worker-types/{type}/instances -> Workers.Read
POST scale up/down/set -> Workers.Scale
PUT scale-settings -> Workers.Admin
pause/resume -> Workers.Scale
```

### Safety Rules

- Reject scale commands where desired replicas are outside min/max.
- Reject negative values.
- Reject max replicas over global configured ceiling.
- Reject unknown worker type unless it is currently registered.
- Record all scale attempts.
- Do not expose Kubernetes credentials to the web UI.
- Do not mount Docker socket into `Argus.Web` or `RealtimeService` for MVP.
- Kubernetes scaling must use least-privilege RBAC: only patch scale subresource for Argus worker deployments.

Global ceiling:

```json
{
  "Workers": {
    "GlobalMaxReplicasPerType": 100
  }
}
```

## Configuration

Add to `Argus.RealtimeService` config:

```json
{
  "Workers": {
    "HeartbeatTimeoutSeconds": 45,
    "SaturationThresholdPercent": 90,
    "GlobalMaxReplicasPerType": 100,
    "ScalerKind": "NoOp",
    "KubernetesNamespace": "argus"
  }
}
```

Supported `ScalerKind` values:

```text
NoOp
Kubernetes
ExternalCommand
```

Dependency registration:

```csharp
builder.Services.Configure<WorkerOptions>(builder.Configuration.GetSection("Workers"));
builder.Services.AddSingleton<IWorkerTypeCatalog, WorkerTypeCatalog>();
builder.Services.AddScoped<IWorkerSummaryService, WorkerSummaryService>();
builder.Services.AddScoped<IWorkerScaleSettingsService, WorkerScaleSettingsService>();
builder.Services.AddScoped<IWorkerScaleCommandService, WorkerScaleCommandService>();

var scalerKind = builder.Configuration["Workers:ScalerKind"] ?? "NoOp";

if (scalerKind.Equals("Kubernetes", StringComparison.OrdinalIgnoreCase))
{
    builder.Services.AddSingleton<IWorkerScaler, KubernetesWorkerScaler>();
}
else if (scalerKind.Equals("ExternalCommand", StringComparison.OrdinalIgnoreCase))
{
    builder.Services.AddSingleton<IWorkerScaler, ExternalCommandWorkerScaler>();
}
else
{
    builder.Services.AddSingleton<IWorkerScaler, NoOpWorkerScaler>();
}
```
