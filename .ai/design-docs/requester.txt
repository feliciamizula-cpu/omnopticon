
# SPEC-1-HTTP-Request-Response-Tool

## Background

Argus needs a production-ready HTTP Request/Response Tool inside `Argus.Web`.

The tool must behave like a repeater/viewer for HTTP evidence linked to Argus assets. Any eligible asset should be configurable to show a `Send to Request Tool` context-menu action. Selecting that action navigates to a dedicated page that shows the original HTTP request/response pair used to confirm that asset. The page must support all request/response pairs linked to that asset as tabs. User-generated replays must also appear as new tabs. Users must be able to edit and resend requests, compare requests or responses, and preserve all history as durable evidence.

This design intentionally defers the scripting engine to a future phase, but the MVP must be structured so future scripted request chains can reuse the same session, exchange, storage, audit, diff, and execution infrastructure.

Confirmed product decisions:

- Do not hard-block out-of-scope requests in the MVP.
- Do not require a per-send confirmation for out-of-scope or unknown targets.
- Compute and store scope status anyway.
- Implement a new bounded backend service named `Argus.RequestToolService`.
- Store recent (24h) request/response bodies inline in PostgreSQL.
- Store older request/response bodies through the existing artifact/storage pattern.
- Implement this as a page in `Argus.Web`.
- Use tabbed request/response history per asset.
- Future scripting is out of scope, but the schema and APIs must be scripting-ready.

## Requirements

### Must Have

- Add a new `Argus.RequestToolService` backend service.
- Add new request-tool contracts under `src/Contracts/Argus.Contracts/RequestTool/`.
- Add a new `Argus.Web` page at `/request-tool/{assetId:guid}`.
- Any eligible asset can expose `Send to Request Tool`.
- The first implementation must add this action to the existing Assets page row actions.
- The action must be policy-driven so additional asset pages can opt in later.
- Opening the tool for an asset must create or load a durable session for that asset.
- The tool must display the original request/response pair used to confirm the asset whenever available.
- If the original pair cannot be reconstructed, create an editable synthetic request from asset URL metadata.
- The window must show every request/response exchange for the selected asset in a tabbed interface.
- Sending a request from the UI must create a new immutable exchange tab.
- Users must be able to edit:
  - Method
  - URL
  - Query string
  - Headers
  - Cookies
  - Body text
  - Content type
  - Follow-redirects flag

  - Request headers
  - Request body
  - Full raw request
  - Response headers
  - Response body
  - Full raw response

  - Status code
  - Reason phrase

  - Scope status
  - Sent/completed time
- Allow tab rename.

- Save reusable request templates.

- Add scripting execution groups in a later phase.

## Method

### Architecture Overview

Add `Argus.RequestToolService` as a new service in the existing Aspire architecture.

The service owns:

- Request-tool sessions
- HTTP exchanges
- Replay execution
- Scope classification result storage
- Diff generation
- Request/response raw rendering
- Audit rows
- Large-body artifact integration
- Future scripting extension points

It depends on existing platform services:

- `AssetService` to load asset context
- `ArtifactService` to store large bodies and reconstruct evidence when possible
- `ProgramScopeService` to classify scope
- `RateLimitService` to enforce rate limits
- `ProxyRegistryService` to resolve proxies
- `RealtimeService` or RabbitMQ event publication for UI notifications if already used consistently elsewhere
- PostgreSQL `argusdb` for normalized metadata
- Redis if needed for transient locks/cache, though the MVP can rely on RateLimitService for throttling

## Domain Model

### Terms

- Session: durable request-tool workspace for one asset.
- Exchange: immutable request/response pair.
- Draft: UI-only editable request derived from an exchange or constructed from scratch.
- Original evidence: exchange reconstructed from the request/response pair that confirmed the asset.
- Replay: user-sent request.
- Parent exchange: previous exchange used as the source for a clone/replay.
- Body artifact: external artifact reference for large request/response body storage.
- Scope status: classification of the requested target at send time.

### Exchange Lifecycle

```plantuml
@startuml
[*] --> Draft

Draft --> Sending : user clicks Send
Sending --> Completed : response captured
Sending --> Failed : network error / timeout / rate-limit denial

Completed --> ClonedDraft : clone
Failed --> ClonedDraft : clone
ClonedDraft --> Sending : user edits and sends

Completed --> Compared : compare selected
Failed --> Compared : compare selected
Compared --> Completed

Completed --> Pinned : pin
Pinned --> Completed : unpin

Completed --> [*]
Failed --> [*]
@enduml
```

### Body Storage Thresholds

Add config options:

```json
{
  "RequestTool": {
    "InlineBodyThresholdBytes": 65536,
    "PreviewBodyThresholdBytes": 1048576,
    "MaxBodyBytes": 26214400,
    "DefaultTimeoutSeconds": 30,
    "MaxRedirects": 10,
    "AllowOutOfScopeSend": true,
    "RequireOutOfScopeConfirmation": false,
    "RedactSecretsInAudit": true,
    "UserAgent": "Argus-RequestTool/1.0"
  }
}
```

Rules:

- If body size <= `InlineBodyThresholdBytes`, store body inline.
- If body size > `InlineBodyThresholdBytes`, store body as an artifact and store only artifact ID/hash/size in `http_exchanges`.
- If body size > `PreviewBodyThresholdBytes`, return truncated preview in detail endpoints unless raw endpoint is explicitly called.
- If body size > `MaxBodyBytes`, abort reading further, store truncated body artifact if useful, mark metadata as truncated, and surface warning.
- Never store unbounded response streams in memory.

## API Endpoints

Implement minimal APIs under `/request-tool`.

### Route Summary

```http

GET    /request-tool/sessions/{sessionId:guid}
GET    /request-tool/sessions/{sessionId:guid}/exchanges
GET    /request-tool/exchanges/{exchangeId:guid}

PATCH  /request-tool/exchanges/{exchangeId:guid}/title
PATCH  /request-tool/exchanges/{exchangeId:guid}/pin

POST   /request-tool/compare
GET    /request-tool/exchanges/{exchangeId:guid}/raw-request
GET    /request-tool/exchanges/{exchangeId:guid}/raw-response
GET    /request-tool/health
```

### Endpoint Behavior

#### `GET /request-tool/assets/{assetId}/session`

- Return existing session by asset ID.
- If session does not exist, return 404.
- UI can call POST to create.

#### `POST /request-tool/assets/{assetId}/session`

- Load asset from `AssetService`.
- Create session if not exists.
- Try to hydrate original evidence.
- Return session with exchange summaries.

Hydration priority:

1. Existing `http_exchanges` for asset.
2. Asset metadata containing original request/response.
3. Artifacts linked to asset:
   - `RawResponse`
   - `HarFile`
   - `FindingEvidence`
   - `TextLog`
   - `JsonReport`
4. Asset URL metadata.
5. Synthetic `GET` request if only a URL can be inferred.

#### `GET /request-tool/sessions/{sessionId}`

- Return session plus exchange summaries.

#### `GET /request-tool/exchanges/{exchangeId}`

- Return full exchange detail.
- Include inline body if inline.
- Include preview body if artifact body is small enough or preview exists.
- Do not return huge artifact body by default.

#### `POST /request-tool/exchanges/{exchangeId}/clone`

- Load exchange.
- Create a new UI draft DTO from that exchange.
- Do not persist the draft as an exchange unless the user sends it.
- Return `HttpExchangeDetailDto`-compatible draft object with a temporary client-side ID if needed.
- Alternative acceptable implementation: return `SendHttpRequestToolRequest` initialized from the exchange.

#### `POST /request-tool/sessions/{sessionId}/send`

- Validate request.
- Normalize URL.
- Classify scope.
- Call rate-limit service.
- Send request server-side if rate limit allows.
- Persist immutable exchange.
- Audit.
- Return `HttpExchangeDetailDto`.

Important: Do not block out-of-scope/unknown scope in MVP.

#### `POST /request-tool/compare`

- Load left and right exchanges.
- Render selected target to comparable text.
- Use DiffPlex to produce unified and side-by-side diff.
- Return both raw compared text and diff models.

#### Raw endpoints

- `GET /raw-request` returns canonical raw HTTP request text.
- `GET /raw-response` returns canonical raw HTTP response text.
- Support query parameter `download=true` to set attachment headers.

## HTTP Replay Algorithm

```plantuml
@startuml
start
:Receive SendHttpRequestToolRequest;
:Validate session exists;
:Validate method, URL, headers, cookies, body size;
:Normalize URL into scheme/host/port/path/query;
:Load session asset/program;
:Classify scope via ProgramScopeService;
note right
MVP rule:
Do not block OutOfScope or Unknown.
Store the classification only.
end note

:Build rate-limit key;
:Call RateLimitService;
if (allowed?) then (yes)
  :Resolve proxy if ProxyId is provided;
  :Create HttpRequestMessage;
  :Apply headers and cookies;
  :Attach body if method allows body;
  :Set timeout/cancellation;
  :Send using HttpClient;
  :Capture status, headers, response body stream, timing;
  if (redirect and FollowRedirects) then (yes)
    :Follow redirect up to MaxRedirects;
    :Capture each RedirectHop;
  endif
  if (body size <= InlineBodyThreshold) then (yes)
    :Store body inline;
  else (no)
    :Store body through ArtifactService;
    :Persist artifact id, size, sha256;
  endif
  :Persist http_exchange with Completed outcome;
  :Write audit row;
  :Publish RequestToolExchangeCreatedEvent;
  :Return detail DTO;
else (no)
  :Persist failed exchange with RateLimited outcome;
  :Write audit row;
  :Return 429 with retry metadata and exchange id;
endif
stop
@enduml
```

### Send Validation Rules

- Allowed methods:
  - GET
  - POST
  - PUT
  - PATCH
  - DELETE
  - HEAD
  - OPTIONS
  - TRACE may be disabled by default unless config allows it.
- URL must be absolute HTTP or HTTPS.
- Reject non-HTTP schemes.
- Reject CRLF injection in method, URL, header names, and header values.
- Reject invalid header names.
- Reject request body over configured `MaxBodyBytes`.
- Allow request body for all methods except HEAD. Do not artificially block body on GET because some testing workflows require it, but show no special warning.
- Do not allow users to set hop-by-hop transport headers directly if `HttpClient` owns them:
  - Connection
  - Keep-Alive
  - Transfer-Encoding
  - Upgrade
  - Proxy-Connection
- Handle `Host` specially:
  - If user sets Host, use it as request Host header if supported.
  - The TCP target still comes from the URL unless future proxy/raw-socket support is added.
- Ensure cookies are merged into a single `Cookie` header unless user has manually set a `Cookie` header; in that case, preserve manual header and show cookies grid as derived/locked.

### Redirect Handling

Use manual redirect handling so each hop is captured.

Rules:

- `FollowRedirects = false`: store only first response.
- `FollowRedirects = true`: follow up to `MaxRedirects`.
- Store redirect chain as JSONB.
- For 301/302/303, convert non-GET/HEAD to GET unless preserving method is explicitly configured.
- For 307/308, preserve method and body.
- Resolve relative `Location` against previous URL.
- Do not drop audit data for intermediate responses.
- For MVP, persist final response body only and persist redirect chain metadata. Later enhancement can persist each hop as child exchanges.

### Timeout Handling

- Default request timeout: 30 seconds.
- Use cancellation tokens.
- Store `NetworkError` outcome for timeout.
- Store error message redacted and normalized.
- Do not throw unhandled exceptions to UI.

### TLS Metadata

Capture if available:

- Protocol
- Cipher suite, if available
- Certificate subject
- Certificate issuer
- NotBefore
- NotAfter
- Thumbprint

If unavailable, leave `tls_info` null.

## Scope Classification

The MVP must compute scope but not block sending.

### Rules

- Call existing program-scope/scope-validation endpoint if available.
- If the endpoint is unavailable, classify as `Unknown`.
- If classification fails due to transient service error, classify as `Unknown` and continue.
- Persist result in `http_exchanges.scope_status`.
- Show scope status in UI.
- Do not show a confirmation dialog.
- Do not block out-of-scope sends.

### Pseudocode

```csharp
public async Task<RequestToolScopeStatus> ClassifyAsync(Guid programId, Uri uri, CancellationToken ct)
{
    try
    {
        var result = await programScopeClient.ValidateTargetAsync(programId, uri.ToString(), ct);
        return result.Status switch
        {
            "InScope" => RequestToolScopeStatus.InScope,
            "OutOfScope" => RequestToolScopeStatus.OutOfScope,
            "Excluded" => RequestToolScopeStatus.Excluded,
            "NeedsReview" => RequestToolScopeStatus.NeedsReview,
            _ => RequestToolScopeStatus.Unknown
        };
    }
    catch
    {
        return RequestToolScopeStatus.Unknown;
    }
}
```

```csharp
private async Task<string> RenderTargetAsync(HttpExchange exchange, RequestToolCompareTarget target, CancellationToken ct)
{
    return target switch
    {
        RequestToolCompareTarget.RequestHeaders => RenderHeaders(exchange.RequestHeaders),
        RequestToolCompareTarget.RequestBody => await bodyStorage.GetFullBodyAsync(exchange.RequestBodyArtifactId, exchange.RequestBodyInline, ct) ?? "",
        RequestToolCompareTarget.RawRequest => await rawRenderer.RenderRequestAsync(exchange, ct),
```

```javascript
window.argusRequestToolMonaco = {
  editors: {},

  createEditor: function (elementId, value, language, readOnly) {
    const el = document.getElementById(elementId);
    if (!el || !window.monaco) return false;

    if (this.editors[elementId]) {
      this.editors[elementId].dispose();
    }

    this.editors[elementId] = monaco.editor.create(el, {
      value: value || "",
      language: language || "plaintext",
      readOnly: !!readOnly,
      automaticLayout: true,
      minimap: { enabled: false },
      scrollBeyondLastLine: false,
      wordWrap: "on"
    });

    return true;
  },

  getValue: function (elementId) {
    const editor = this.editors[elementId];
    return editor ? editor.getValue() : null;
  },

  setValue: function (elementId, value) {
    const editor = this.editors[elementId];
    if (editor) editor.setValue(value || "");
  },

  createDiffEditor: function (elementId, left, right, language) {
    const el = document.getElementById(elementId);
    if (!el || !window.monaco) return false;

    if (this.editors[elementId]) {
      this.editors[elementId].dispose();
    }

    const diffEditor = monaco.editor.createDiffEditor(el, {
      automaticLayout: true,
      readOnly: true,
      minimap: { enabled: false },
      scrollBeyondLastLine: false
    });

    const original = monaco.editor.createModel(left || "", language || "plaintext");
    const modified = monaco.editor.createModel(right || "", language || "plaintext");
    diffEditor.setModel({ original, modified });

    this.editors[elementId] = diffEditor;
    return true;
  },

  dispose: function (elementId) {
    const editor = this.editors[elementId];
    if (editor) {
      editor.dispose();
      delete this.editors[elementId];
    }
  }
};
```

```csharp
public static string DetectMonacoLanguage(string? contentType, string? url)
{
    if (contentType?.Contains("json", StringComparison.OrdinalIgnoreCase) == true) return "json";
    if (contentType?.Contains("html", StringComparison.OrdinalIgnoreCase) == true) return "html";
    if (contentType?.Contains("xml", StringComparison.OrdinalIgnoreCase) == true) return "xml";
    if (contentType?.Contains("javascript", StringComparison.OrdinalIgnoreCase) == true) return "javascript";
    if (contentType?.Contains("css", StringComparison.OrdinalIgnoreCase) == true) return "css";
    if (contentType?.Contains("x-www-form-urlencoded", StringComparison.OrdinalIgnoreCase) == true) return "plaintext";
    if (url?.EndsWith(".js", StringComparison.OrdinalIgnoreCase) == true) return "javascript";
    if (url?.EndsWith(".css", StringComparison.OrdinalIgnoreCase) == true) return "css";
```

## API Client in Argus.Web

```csharp
using System.Net.Http.Json;
using Argus.Contracts.RequestTool;

public sealed class RequestToolApiClient(HttpClient httpClient)
{
    public async Task<RequestToolSessionDto> CreateOrGetSessionAsync(Guid assetId, CancellationToken ct = default)
    {
        var response = await httpClient.PostAsJsonAsync($"/request-tool/assets/{assetId}/session", new CreateOrGetRequestToolSessionRequest(assetId), ct);
        response.EnsureSuccessStatusCode();
        return await response.Content.ReadFromJsonAsync<RequestToolSessionDto>(cancellationToken: ct)
            ?? throw new InvalidOperationException("Request-tool session response was empty.");
    }

    public async Task<RequestToolSessionDto> GetSessionAsync(Guid sessionId, CancellationToken ct = default)
    {
        return await httpClient.GetFromJsonAsync<RequestToolSessionDto>($"/request-tool/sessions/{sessionId}", ct)
            ?? throw new InvalidOperationException("Request-tool session response was empty.");
    }

    public async Task<HttpExchangeDetailDto> GetExchangeAsync(Guid exchangeId, CancellationToken ct = default)
    {
        return await httpClient.GetFromJsonAsync<HttpExchangeDetailDto>($"/request-tool/exchanges/{exchangeId}", ct)
            ?? throw new InvalidOperationException("HTTP exchange response was empty.");
    }

    public async Task<HttpExchangeDetailDto> SendAsync(Guid sessionId, SendHttpRequestToolRequest request, CancellationToken ct = default)
    {
        var response = await httpClient.PostAsJsonAsync($"/request-tool/sessions/{sessionId}/send", request, ct);
        response.EnsureSuccessStatusCode();
        return await response.Content.ReadFromJsonAsync<HttpExchangeDetailDto>(cancellationToken: ct)
            ?? throw new InvalidOperationException("Send response was empty.");
    }

    public async Task<SendHttpRequestToolRequest> CloneAsync(Guid exchangeId, CancellationToken ct = default)
    {
        var response = await httpClient.PostAsJsonAsync($"/request-tool/exchanges/{exchangeId}/clone", new CloneHttpExchangeRequest(null), ct);
        response.EnsureSuccessStatusCode();
        return await response.Content.ReadFromJsonAsync<SendHttpRequestToolRequest>(cancellationToken: ct)
            ?? throw new InvalidOperationException("Clone response was empty.");
    }

    public async Task<CompareHttpExchangeResponse> CompareAsync(CompareHttpExchangeRequest request, CancellationToken ct = default)
    {
        var response = await httpClient.PostAsJsonAsync("/request-tool/compare", request, ct);
        response.EnsureSuccessStatusCode();
        return await response.Content.ReadFromJsonAsync<CompareHttpExchangeResponse>(cancellationToken: ct)
            ?? throw new InvalidOperationException("Compare response was empty.");
    }
}
```

## Evidence Hydration

When opening an asset for the first time, the service must try to populate the original exchange.

### Hydration Algorithm

```plantuml
@startuml
start
:Load asset by assetId;
if (session exists?) then (yes)
  :Return session;
  stop
endif

:Create session;
:Search existing request-tool exchanges;
if (found?) then (yes)
  :Attach summaries;
  :Return session;
  stop
endif

:Inspect asset metadata for request/response evidence;
if (complete request/response found?) then (yes)
  :Create OriginalEvidence exchange;
  :Return session;
  stop
endif

:Search artifacts linked to asset;
if (HAR found?) then (yes)
  :Parse first matching HAR entry;
  :Create OriginalEvidence exchange;
  :Return session;
  stop
endif

if (RawResponse found?) then (yes)
  :Create response-only OriginalEvidence;
  :Infer request from asset URL;
  :Return session;
  stop
endif

if (URL can be inferred?) then (yes)
  :Create Synthetic GET exchange without response;
  :Return session;
  stop
else (no)
  :Return session with no exchanges and UI error;
  stop
endif
@enduml
```

### Asset URL Inference

Try fields in order:

1. Asset metadata URL field.
2. Asset display name if absolute URL.
3. Asset value if absolute URL.
4. For host/subdomain asset, synthesize `https://{host}/`.
5. Otherwise no synthetic request.

### HAR Parsing

If an artifact of type `HarFile` exists:

- Parse JSON.
- Locate first entry matching asset URL/host.
- Extract:
  - Request method
  - URL
  - Headers
  - Cookies
  - Body
  - Response status
  - Response headers
  - Response body text if present
  - Timings
- Store as `OriginalEvidence`.

## Security and Safety

### SSRF Risk

This is a server-side HTTP sender and therefore creates SSRF risk.

MVP decision says do not hard-block out-of-scope targets. However, the implementation must still protect Argus infrastructure.

Hard-block these targets even in MVP:

- `localhost`
- `127.0.0.0/8`
- `::1`
- Link-local ranges
- RFC1918 private ranges unless config explicitly allows internal testing
- Cloud metadata endpoints:
  - `169.254.169.254`
  - IPv6 metadata equivalents
- Docker bridge ranges unless explicitly allowed
- Kubernetes service ranges unless explicitly allowed

Add config:

```json
{
  "RequestTool": {
    "AllowPrivateNetworkTargets": false,
    "AllowLocalhostTargets": false,
    "AllowCloudMetadataTargets": false
  }
}
```

Rationale: This does not conflict with the product decision not to block out-of-scope public targets. It prevents the Request Tool from being abused to attack Argus itself or its cloud runtime.

### DNS Rebinding Defense

Before sending:

- Resolve host.
- Check resolved IPs against blocked ranges.
- Use the resolved IP information for decisioning.
- Re-check after redirects.
- If the host resolves to blocked IP ranges, block with `ValidationError`.

### Header Injection Defense

Reject header names/values containing raw CR or LF.

### Response Handling Defense

- Do not render HTML response bodies as live DOM.
- Show HTML as text in Monaco/editor.
- If adding preview iframe later, sandbox it with no scripts and no network.
- Avoid storing huge unbounded bodies.
- Do not decompress zip bombs beyond max byte limit.
- Sanitize filenames for downloads.

### Audit

Audit actions:

```text
SessionOpened
SessionCreated
OriginalEvidenceHydrated
SyntheticRequestCreated
ExchangeCloned
RequestSent
RequestRateLimited
RequestFailed
ExchangeCompared
ExchangePinned
ExchangeRenamed
RawRequestDownloaded
RawResponseDownloaded
```

Audit metadata must be redacted.

## Gathering Results

### Functional Acceptance Criteria

- From the Assets page, an eligible asset has `Send to Request Tool`.
- Selecting it navigates to `/request-tool/{assetId}`.
- The Request Tool loads a session for that asset.
- The original evidence appears when available.
- A synthetic request appears when original evidence is unavailable but URL can be inferred.
- User can edit method, URL, headers, cookies, body, and content type.
- User can send the edited request.
- A new tab appears for the sent request.
- Response status, headers, body, timing, size, and errors are visible.
- User can clone a previous exchange.
- User can compare two requests.
- User can compare two responses.
- Large bodies are stored as artifacts.
- Small bodies are stored inline.
- All send attempts create audit rows.
- Scope status is shown but not blocking.
- Rate-limit denial is handled gracefully.
- Sensitive values are redacted from audit/log surfaces.
- Private/internal infrastructure targets are blocked unless explicitly configured.

### Performance Targets

- Session load with 50 exchanges: under 500 ms server time.
- Exchange detail load for inline body: under 300 ms server time.
- Send overhead excluding remote target latency: under 150 ms.
- Diff for 1 MB text bodies: under 2 seconds.
- UI remains responsive with 100 exchange tabs by lazy-loading details.

### Reliability Targets

- No unhandled exceptions for network failures.
- Failed sends persist as failed exchanges.
- Body storage failures return clear errors.
- Repeated session creation is idempotent per asset.
- Duplicate browser refresh does not duplicate original evidence.

### Security Targets

- Audit rows contain no raw Authorization/Cookie secrets.
- Server-side sender cannot reach protected internal/cloud metadata targets unless explicitly configured.
- HTML responses are never executed in the app.
- Header injection attempts are rejected.
- Oversized bodies are truncated or rejected according to config.
