Question - Why are we using two different types of backend databases, sqllite and postgres? Shouldn't we just standardize, I'd say on postgres? Is this because we are doing something like building a package from source, and that package happens to already use sqllite? Or is this our design decision?

ANSWER (Claude) - It's neither a hard requirement nor a deliberate design decision worth keeping; it's incidental drift. The core services (Asset, Finding, Task, ProgramScope, Agent, Artifact, etc.) all use the shared Postgres `argusdb`. Only two services were written against SQLite: RealtimeService (worker registry, scale settings, events) and ProxyRegistryService. Nothing builds SQLite from source or depends on it externally — it was just the lighter path when those two services were first scaffolded for local dev. There's no reason not to standardize on Postgres, and doing so removes a class of bugs (e.g. SQLite can't translate `string.Equals(..., OrdinalIgnoreCase)` to SQL, which is exactly what was 500-ing the Workers page). I'm migrating both services to the shared Postgres `argusdb`. Agreed on standardizing on Postgres.
