## Critical Findings

### 1. CRITICAL: Password Exposed in API Response
**Files:** `src/Contracts/Argus.Contracts/Proxies/ProxyContracts.cs:8`, `src/Services/Argus.ProxyRegistryService/Program.cs:232-252`

The `ProxyDto` record includes `Password` as a plain string, and the `ToDto` method exposes it directly in API responses:

```csharp
// ProxyContracts.cs:8
string? Password,

// Program.cs:239
r.Password,
```

**Impact:** Proxy credentials (including passwords) are returned in plaintext to all API consumers via `/proxies` and `/proxies/{id}` endpoints.

**Recommendation:** Remove `Password` from `ProxyDto` entirely, or create a separate `ProxyDtoPublic` that excludes sensitive fields. Never return passwords in API responses.

### 2. CRITICAL: Depth Check Ordering Bug in InMemoryAssetStore.GetSubgraphAsync
**File:** `src/Services/Argus.AssetService/Program.cs:553-588`

```csharp
while (queue.TryDequeue(out var current))
{
    if (maxDepth.HasValue && current.Depth >= maxDepth.Value)  // Check depth BEFORE visited check
        continue;

    var neighbors = _relationships.Values
        .Where(r => r.FromAssetId == current.AssetId)
        .Select(r => r.ToAssetId)
        .Where(id => !visited.Contains(id));  // visited check after depth check
```

**Issue:** When a node is reached through different paths at different depths (e.g., A→B→C at depth 2, then A→D→C at depth 1), the node at depth 1 might be processed after depth 2 was already exceeded, skipping valid shorter paths.

**Fix:** Reorder to check visited status first:
```csharp
while (queue.TryDequeue(out var current))
{
    if (visited.Contains(current.AssetId))
        continue;
    visited.Add(current.AssetId);

    if (maxDepth.HasValue && current.Depth >= maxDepth.Value)
        continue;
    // ... rest of loop
}
```

## Security Concerns

### 3. Webhook Secret in HTTP Headers
**File:** `src/Services/Argus.RealtimeService/WebhookService.cs:183-186`

```csharp
if (!string.IsNullOrWhiteSpace(config.SecretHeader) && !string.IsNullOrWhiteSpace(config.SecretValue))
{
    request.Headers.TryAddWithoutValidation(config.SecretHeader, config.SecretValue);
}
```

**Concern:** Secrets transmitted in headers may be logged by proxies, web servers, or monitoring systems. Consider using HMAC signatures or other non-replayable authentication methods instead of static header values.

## Code Quality Issues

### 5. Missing Null Check in AssetService Subgraph Query
**File:** `src/Services/Argus.AssetService/Program.cs:827-831`

```csharp
if (assetTypes is not null && assetTypes.Count > 0)
{
    var typeNames = assetTypes.Select(t => t.ToString()).ToArray();
    sql.Append(" AND a.type = ANY(@assetTypes)");
}
```

**Issue:** The SQL condition is appended but the condition is not properly gated. When `assetTypes` is null or empty, the append logic correctly doesn't execute, but the `Sql.Append` on line 830 is not the issue - it's that the `assetTypes` parameter may need `string[]` type handling for PostgreSQL `ANY()`.

**Note:** This works with Dapper's parameter handling for arrays.

### 6. Database Query in Hot Path
**File:** `src/Services/Argus.RealtimeService/WebhookService.cs:77-83`

```csharp
using (var scope = _scopeFactory.CreateScope())
{
    var dbContext = scope.ServiceProvider.GetRequiredService<WebhookDbContext>();
    activeConfigs = await dbContext.WebhookConfigs
        .Where(c => c.IsActive)
        .ToListAsync(cancellationToken);
}
```

**Issue:** Database query on every event in `ProcessEvent`. Under high event volume, this creates database load.

**Recommendation:** Consider caching webhook configs with a short TTL or using a refresh interval pattern.

### 7. Unbounded Retry Delay in WebhookService
**File:** `src/Services/Argus.RealtimeService/WebhookService.cs:228`

```csharp
var delay = TimeSpan.FromSeconds(Math.Pow(2, attempt - 1));
```

**Issue:** Exponential backoff is good, but for high retry counts, delays become very long (2^6 = 64 seconds). Consider capping at a reasonable max (e.g., 30 seconds).
