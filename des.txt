# SPEC-2-provider-usage-monitoring

## Background

The Development section currently manages development agents, agent tasks, schedules, and coordinator chat. The next reliability risk is provider exhaustion: agents can silently stop making progress when OpenAI/Codex, Anthropic/Claude, OpenRouter, DeepSeek, Gemini, Qwen/DashScope, or OpenCode-backed providers run out of credits, messages, tokens, requests, or rolling-window quota.

This feature adds a provider usage dashboard and monitor under the Development section. It retrieves remaining usage from provider APIs where available, records inferred usage from agent execution where APIs are unavailable, and warns before agent runs are blocked by provider limits.

## Requirements

### Must

* Show remaining usage for every configured provider account used by Development agents.
* Support provider status values: `healthy`, `warning`, `critical`, `exhausted`, `not_configured`, `unknown`, `error`, and `stale`.
* Poll official provider APIs when credentials are configured.
* Track observed agent/provider calls locally even when official remaining-usage APIs are not available.
* Show latest usage, reset time, unit, source, confidence, last refresh time, and raw error summary.
* Warn at configurable thresholds, defaulting to warning at 25% remaining and critical at 10% remaining.
* Include Blazor UI route `/development/provider-usage` with the same Development visual style as Agents and Agent Tasks.
* Add BFF proxy endpoints in `Argus.Web` so the UI never calls provider APIs directly.
* Never store API keys in the database.
* Work out of the box with seeded demo provider accounts and `not_configured` cards when secrets are missing.
* Add tests for normalization, threshold calculation, and each provider adapter's sample response parsing.

### Should

* Link usage cards to agents using that provider/tool/model.
* Allow manual refresh per provider and refresh all.
* Allow pausing all agents for a provider from the provider usage page.
* Publish an internal event when a provider crosses warning or critical thresholds.
* Keep at least 14 days of snapshots for trend charts.

### Could

* Show projected exhaustion time based on recent consumption rate.
* Add automatic provider fallback recommendations for pending tasks.
* Add per-agent/provider cost attribution.

### Won't

* Scrape provider web dashboards.
* Put provider secrets in Blazor, browser local storage, logs, or database records.
* Block all agents automatically in the first implementation; instead provide operator-visible warnings and manual pause controls.

## Method

### Placement

Implement this inside `Argus.AgentService` first because this is a Development feature and uses the same provider concepts as agents: `Tool`, `Model`, and active task execution.

Do not extend `Argus.RateLimitService` for this. That service protects scan targets and worker traffic. Provider usage is about external AI/provider quota and belongs with Development agent orchestration.

### Adapter behavior

#### OpenAI

Use Admin API credentials. Poll organization usage/cost endpoints. Store cost snapshots by day/month and derive remaining only when a local monthly budget is configured in `ProviderAccountRecord.ConfigJson` or environment settings.

Result windows:

* `day` / `usd` / source `api`
* `month` / `usd` / source `api+configured_budget`
* optional token windows if usage endpoint data is added

If no budget is configured, show spend used and `remaining = null`, status `unknown` rather than guessing.

#### Anthropic

Use Admin API credentials. Poll organization usage and cost report endpoints. For Claude Code business/org accounts, store daily aggregated usage if available. Derive remaining only from known spend limit/rate-limit data or configured budget.

Result windows:

* `day` / `tokens` / source `api`
* `month` / `usd` / source `api+configured_budget`
* `daily_claude_code` / provider-specific unit if the endpoint returns Claude Code metrics

#### OpenRouter

Use `/api/v1/key` for per-key limit and remaining credits. Optionally use `/api/v1/credits` with a management key for user-level total credits minus usage.

Result windows:

* `key_limit` / `credits` / source `api`
* `account_balance` / `credits` / source `api`

#### DeepSeek

Use `/user/balance`. Store one snapshot per returned currency. `total_balance` is remaining balance. If `is_available=false`, status becomes `exhausted`.

Result windows:

* `balance` / `usd` or `cny` / source `api`

#### Gemini

Use Google Cloud quota/service usage APIs where credentials and project id are configured. Track quota metrics for Generative Language API or Vertex AI/Gemini service. For billing-cap monitoring, optionally read configured monthly budget from Argus config.

Result windows:

* `minute` / `requests` / source `cloud_quota_api`
* `day` / `requests` / source `cloud_quota_api`
* `month` / `usd` / source `configured_budget`

#### Qwen / DashScope

The first implementation should support the provider account and local observed usage ledger. If no official remaining-quota API is available for the configured account, status should be `unknown` or `not_configured`. Do not scrape the console.

Result windows:

* `observed_day` / `requests` / source `local_ledger`
* `manual_free_quota` / `tokens` / source `manual`, if the operator enters values from the console

#### Codex CLI subscription

When using ChatGPT/Codex plan auth rather than API-key mode, remaining quota is primarily visible in the Codex dashboard or active CLI session status. Implement a conservative local adapter:

* Record every Codex agent invocation.
* Classify limit errors from stderr/stdout.
* Store latest known limit message and reset hints.
* Allow manual snapshot entry for remaining plan usage.
* Mark confidence `low` unless an official machine-readable status becomes available.

#### Claude Code subscription

When using Claude plan auth rather than API-key mode, implement the same conservative local adapter:

* Record every Claude agent invocation.
* Classify `rate_limit_error`, `usage limit`, `weekly limit`, and credit fallback prompts.
* Allow manual snapshot entry for remaining plan usage.
* Mark confidence `low` unless organization Admin API usage data is configured.

### Status calculation

```csharp
public static string CalculateStatus(
    ProviderAccountRecord account,
    ProviderUsageSnapshotRecord snapshot,
    DateTimeOffset now)
{
    if (!account.Enabled) return "unknown";
    if (snapshot.Source == "not_configured") return "not_configured";
    if (snapshot.Status == "error") return "error";
    if (snapshot.ObservedAt < now.AddMinutes(-30)) return "stale";

    if (snapshot.RemainingAmount is <= 0) return "exhausted";

    if (snapshot.RemainingPercent is decimal pct)
    {
        if (pct <= account.CriticalThresholdPercent) return "critical";
        if (pct <= account.WarningThresholdPercent) return "warning";
        return "healthy";
    }

    return "unknown";
}
```

Service --> UI: ProviderUsageSummaryDto

### Error classification

Add `ProviderLimitErrorClassifier`.

Rules:

* Contains `rate_limit_error`, `429`, `rate limit`, `too many requests` -> provider status `critical` unless reset time is present.
* Contains `insufficient balance`, `402`, `quota exceeded`, `usage limit reached`, `weekly limit`, `message limit` -> provider status `exhausted`.
* Contains `invalid api key`, `unauthorized`, `401`, `403` -> provider status `error` with credential message.
* Timeout/network errors -> provider status `error`, not `exhausted`.
